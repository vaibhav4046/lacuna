# Performance report

Measured, not estimated. Every number here names the command that produced it
and the artifact it was read out of. A number with neither does not belong in
this file.

Measured 2026-08-19 at the tag `v7-1-convergence`, against production at
<https://lacuna-five.vercel.app> reading HydraDB Cloud.

## Where the time goes

| Path | Median | What it is |
| --- | --- | --- |
| one question, self-hosted node | 120ms | Cypher over HTTP on loopback, 64 question sweep |
| one question, HydraDB Cloud | 267ms | records addressed by id over the public internet, same 64 questions |
| the store's own relation graph | 59ms | `GET /context/relations`, 47 relations |
| health round trip to the managed service | about 160ms | `/api/health` |

Read out of [artifacts/hydra/cloud-parity.json](artifacts/hydra/cloud-parity.json)
and the live endpoints. The two stores answer the same 64 questions identically,
so the gap between 120ms and 267ms is transport and API shape, not different
work: the node runs one Cypher query where the cloud fetches several records by
id and walks them in the product.

## Under concurrency

300 requests at concurrency 12 against the deployed ask endpoint:

| | |
| --- | --- |
| throughput | about 26 requests a second |
| p50 | 406ms |
| p95 | 809ms |
| p99 | 1965ms |
| max | 2049ms |
| failures | 0 |
| answers that changed under load | 0 |

From [artifacts/soak/soak.json](artifacts/soak/soak.json), written by
`npm run soak`. The correctness half matters more than the latency half: every
response is compared against the answer that question gave when asked alone, so
a run cannot post a good p95 by returning something stale.

The load is deliberately modest. The useful question is whether the system
degrades or misbehaves when several agents share a workspace, not how hard a
free tier can be pushed before a quota runs out.

## What is not measured, and is not claimed

- **No breakdown of model time versus Lacuna time.** Nothing on the answer path
  calls a model, so there is no model time to separate. That is a property of
  the design rather than an omission, and it is why these numbers are small.
- **No two-writer evidence.** The soak covers concurrent readers.
- **No cold start figure.** The deployed function's first request after idle has
  not been isolated from the rest.
- **No official benchmark latency.** See
  [docs/BENCHMARK_LONGMEMEVAL.md](docs/BENCHMARK_LONGMEMEVAL.md) for what an
  official run requires and what has actually been run.

## The context cost, which is the number this project cares about

Lacuna answers all 64 gold questions with a mean of 18 estimated context tokens.
The best baseline reaches 63 of 64 and spends 1843. That ratio, not the
latency, is the claim: the work is deciding what the next agent should receive,
and a smaller correct pack is the product.

From [artifacts/bench/results.json](artifacts/bench/results.json), read in full
in [docs/BENCHMARKS.md](docs/BENCHMARKS.md). The corpus is generated by this
project, so the comparison is fair between the systems it compares and is not a
public benchmark.
