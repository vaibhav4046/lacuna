# Lacuna 100-star launch playbook

A star is a result of earned trust, not the product. This plan aims to create
enough qualified visits for 100 real builders to inspect Lacuna and choose to
follow it. It is not a guarantee.

## Positioning

**Lacuna is temporal, provenance-first memory for agents: it tracks corrections,
exposes conflicts, cites exact evidence and abstains when history cannot support
an answer.**

Primary audience: AI-agent builders, retrieval and memory engineers, MCP users,
open-source infrastructure developers, hackathon judges and technical recruiters.

Primary action: try one failure case in the public workspace.  
Secondary action: inspect the repository evidence or quickstart.  
Star request: only after the project has demonstrated value.

These are planning assumptions. Replace them with actual conversion ratios after
each wave.

## Launch gates

- [ ] Repository description, homepage and topics are set.
- [ ] `web/public/social.png` is uploaded as the GitHub social preview.
- [ ] The live demo works signed out.
- [ ] README communicates the problem, proof and quickstart before deep architecture.
- [ ] One 15-second hook clip and one 45–60-second proof clip exist.
- [ ] Every metric used publicly links to current evidence.
- [ ] The generated 64-question check is never described as official LongMemEval.
- [ ] Ten relevant early users have tried the flow and reported where they stopped believing it.
- [ ] At least two genuinely bounded contribution issues are open.

## Four launch waves

### Wave 0 — private proof

Share the repository with 10–20 relevant builders. Ask only:

> Where did you stop, hesitate or stop believing the claim?

Fix repeated friction before broad distribution. Do not ask for coordinated fake
comments, reciprocal stars or copy-pasted teammate posts.

### Wave 1 — show the contradiction

Lead with a failure ordinary memory systems handle badly. Show Lacuna exposing a
correction, conflict or missing fact before explaining HydraDB or MCP.

Publish in this order:

1. verified repository state and release;
2. LinkedIn native video;
3. X native clip or thread;
4. relevant communities where self-promotion is allowed;
5. direct follow-up to early testers.

### Wave 2 — technical proof

Publish one standalone artifact: architecture, a failure/fix story, provenance
trace, parity test or reproducible benchmark boundary. Link to the exact file or
command that proves it.

### Wave 3 — contribution invitation

Show the public roadmap and two scoped issues. State the files, expected
behaviour and acceptance test. “Contributors welcome” alone is not actionable.

### Wave 4 — meaningful iteration

Ship a user-requested improvement. Publish the before/after result and credit the
reporter. This creates a legitimate second launch instead of reposting the same
announcement.

## Prohibited shortcuts

Do not buy, trade or automate stars. Do not run giveaways tied to starring. Do
not invent users, benchmarks, winners or integrations. Do not tag unrelated
people. Do not replace proof with “revolutionary”, “game-changing” or generic AI
hype.
