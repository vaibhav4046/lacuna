## True competitive risks

1. **Submission eligibility:** no accessible video URL and no submitted form
   means automatic incompleteness regardless of product quality.
2. **HydraDB-native depth:** the production Cloud answer path uses deterministic
   record reads followed by Lacuna-side policy. The native Cypher proof is real
   but self-hosted and separate. A competitor with native traversal directly on
   every production query may score higher here.
3. **Evaluation breadth:** 64/64 is one fixed generated corpus, not LongMemEval
   or independent user data. The caveat protects credibility but cannot replace
   external evaluation.
4. **Product breadth:** voice, broad connectors, private ChatGPT memory,
   packaged SDK and Claude continuity are not accepted capabilities.
5. **Demo clarity:** the film must make the HydraDB/Lacuna division of labour
   obvious within 179 seconds. If it looks like a motion-design reel or hides
   the live product, it will undersell the strongest work.
6. **Mobile graph density:** the graph is usable, but a judge on a narrow screen
   may perceive crowding before switching to the table.
