# Plan

Nine days, solo, one track. The plan is built backwards from what has to be true
on submission day, not forwards from what is easy to start.

**Internal deadline: 2026-08-19, 21:00 Europe/London.** The official deadline is
2026-08-20, 23:59 PT. That gap is emergency buffer, not schedule.

## What must be true at submission

1. A public repository a judge can clone and run, with a `README` whose steps
   actually work on a clean machine.
2. HydraDB doing the load-bearing work, provably, with an ablation that shows
   what breaks without it.
3. A working product, not a benchmark script with a web page bolted on.
4. Numbers a judge can reproduce, produced by a harness in the repository, with
   raw output committed.
5. A video under three minutes that shows the two claims: a superseded fact
   handled correctly, and a structured abstention.
6. Nothing in the repository, the bundle, the screenshots or the video that
   should not be public.

Everything below exists to make one of those six true.

## Order of work, and why

Riskiest assumption first. The riskiest assumption is not "can I build a UI", it
is **"does HydraDB's Cypher subset actually express the queries this design
needs"**. If it does not, the design changes, and it is much cheaper to find that
out on day one than on day six. So the graph adapter and its contract tests come
before any screen.

### Day 1, 2026-08-12: foundation and proof of life

- [x] Capture the rules verbatim, before anything can be claimed about them
- [x] Read upstream HydraDB docs at a pinned commit and record what was read
- [x] Decide track and thesis, written down as ADRs
- [x] Decide the data model against the real Cypher subset, not an imagined one
- [ ] HydraDB running locally by the official source path
- [ ] Real write-read round trip saved as evidence
- [ ] First commit

### Day 2, 2026-08-13: the adapter, and the queries that decide the design

- HTTP client for the HydraDB query API, server-side only, token never leaving
  the server
- Contract tests that run against a live node and fail loudly if it is absent,
  rather than silently mocking
- Every query the design needs, executed for real: `MERGE` upsert, `UNWIND`
  batch write, bounded variable-length traversal, `algo.SPpaths`, the
  `OPTIONAL MATCH` plus `count()` stand-in for `IS NULL`
- Anything the subset refuses gets recorded and designed around the same day

### Day 3, 2026-08-14: ingestion and the demo corpus

- Deterministic synthetic corpus, generated by committed code, not hand-written
  JSON: a launch date revised twice, a cross-session approval, a fact that needs
  two or three hops, a fact that was never stated, a plausible distractor, and
  an unresolved contradiction
- Ingestion pipeline producing claims, spans, and revision edges
- Idempotence proved by ingesting twice and diffing the graph

### Day 4, 2026-08-15: retrieval and abstention

- Query planner: candidate selection, then bounded traversal, then evidence
  assembly
- The abstention decision, with its reason codes, as a pure function over the
  retrieved subgraph so it can be unit tested without a database
- Proof objects: every answer and every abstention carries the traversal that
  produced it

### Day 5, 2026-08-16: the product surface

- Ask, Timeline, Evidence Graph, HydraDB Proof
- Real screenshots at 1920x1080 and 3840x2160, taken from a running build

### Day 6, 2026-08-17: measurement

- Baselines: recency-only, lexical, vector, hybrid, Lacuna
- Metrics: abstention precision, recall, F1, false-answer rate, p50 and p95
  latency, context tokens
- The ablation that turns "we used a graph" into "here is what happens without
  it"
- Raw run output committed, not summarised

### Day 7, 2026-08-18: hardening

- Threat model exercised, not just written: prompt-injection fixtures, namespace
  isolation tests, input limits, query timeouts
- Full Git history secret scan
- Clean-clone run on a fresh path, following the README exactly, with nothing
  from this machine's state

### Day 8, 2026-08-19: submission

- Video script, recorded and cut under three minutes
- Submission fields drafted
- Submit by 21:00 London

### Day 9, 2026-08-20: buffer

Reserved. If it gets used, something went wrong earlier and that is what it is
for.

## What is deliberately not being built

- Any LLM call in the critical path of the demo. The claims are about retrieval
  and abstention. A generated answer on top would make the demo harder to verify
  and easier to doubt.
- A multi-tenant deployment story.
- An ingestion connector for real chat products.

Each of those is a good idea and none of them is what is being judged.

## Risks, ranked

1. **The Cypher subset refuses a query the design depends on.** Highest impact,
   and the reason day 2 is what it is. Mitigation: find out on day 2.
2. **The benchmark shows no advantage.** Then the honest result gets reported and
   the framing changes to where the advantage actually is. Fabricating a number
   is not on the table.
3. **Time.** Solo, nine days. Mitigation: the product surface is four screens,
   not fourteen.
4. **HydraDB local instability under load.** Mitigation: it is pinned to a known
   commit and the failure is visible in the runtime log rather than silent.
